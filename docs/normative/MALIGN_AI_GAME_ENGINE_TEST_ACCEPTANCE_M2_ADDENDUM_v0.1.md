## 1. Alcance y reglas

Este addendum fija exactamente 32 casos canónicos para obligaciones M2 que no tienen ID nominal suficiente en el oracle. No autoriza archivos de test, fixtures, código, schema, migrations, seed, dependencias ni infraestructura.

- Cada ID tiene prioridad, un solo owner y trazabilidad explícita.
- Cada fixture usa versiones pinned y determinísticas; no adopta defaults de producto.
- PASS exige Given/When/Then, post-state, event ordering, artifacts persistentes y projection/privacy aplicables.
- Gate futuro: **32/32 PASS, 0 skips, 0 todo, 0 waivers**.
- Un test suavizado, una aserción omitida o un artifact divergente es FAIL.

## 2. Convenciones de fixture y fuentes

`V0` significa `ruleset=0.1`, `scenario=BASE_2025@0.1`, `registry=<snapshot M2 aprobado>`, `engine_contract=0.1`, `fixture_schema=0.1`, clock fijo, RNG grabado y canonical serialization aprobada. Si el registry M2 aún no está aprobado, un caso que lo requiera no puede implementarse ni pasar.

Fuentes abreviadas:

- `DEC`: DEC-048…059 y DEC-075.
- `ARCH`: Game Engine Implementation Architecture §§12–13, 19, 21, 29–31, 37.
- `DD`: Data Dictionary/ER §§18–19, 28–30.
- `DM`: Game Data Model, state normalizado, append-only history y continuations.
- `CON`: Interface/Command Contract §§4, 6–7, 34–35, 40, 42, 47, 49.
- `ADJ`: Adjudication Engine, scheduler, reactions y lifecycle.
- `SEC`: Information Security Matrix y projection policy.
- `SCN`: Scenario Data, objectives y end-game.
- `REG-CAND`: candidate registry; nunca autoridad de seed hasta aprobación de IQ-M2-010.

En la tabla, `S/E/L/T/O` significa state/events/ledgers/trace/outbox. “Sin artifact” significa que el rechazo no crea ninguno, no que la aserción sea omitida.
